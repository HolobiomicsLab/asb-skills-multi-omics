# snakemake-pipeline-configuration

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Configure and launch the sciL3Pipe Snakemake workflow for sci-L3-seq data: create a sample. from raw FASTQs, write a run-specific config.yaml (output paths, barcode files, mismatch tolerances, cutoffs), and execute via Snakemake with a Docker/Apptainer container and a cluster executor.

## When to use

Use when starting a sci-L3-seq processing run from raw FASTQ files and you must supply config.yaml parameters (rt/tn5/ligation/sss mismatches, barcode lists, cutoff, filters) and sample-to-FASTQ mapping to the Snakemake pipeline.

## When NOT to use

- Data are not sci-L3-seq reads with the three-round combinatorial barcode structure — the Tn5/ligation/SSS barcode files and mismatch parameters in config.yaml are specific to sci-L3
- FASTQs have already been barcode-annotated and trimmed (trimmed. index exists); re-running fastq2.py/config on processed files would duplicate read processing
- A one-off single-sample analysis where a full Snakemake/Docker setup adds overhead without benefit

## Inputs

- Raw paired-end FASTQ files (R1/R2 .fastq.gz) from sci-L3-seq libraries
- Run-specific config.yaml with pipeline input parameters (paths, mismatch tolerances, barcode files, cutoff)
- Barcode resource files: barcode_tn5.txt, barcode_ligation_104.txt, SSS barcode file
- sample. mapping each sample ID to its R1/R2 FASTQ paths (generated by fastq2.py)

## Outputs

- Annotated and trimmed FASTQ files carrying per-read combinatorial barcode, SSS barcode, and UMIs
- trimmed. index file generated by trimmed2.py indexing annotated trimmed FASTQs per sample
- Aligned BAM files (bwa) split into per-single-cell BAMs when split_bam: True
- Pipeline outputs under the configured output_dir/ and temp_dir/ directories

## How to apply

First generate sample. with fastq2.py (optionally symlink raw FASTQs into a fastqs/ folder) so the pipeline knows which R1/R2 FASTQ files belong to each sample. Then write a config.yaml specific to the run: set output_dir (with trailing /), temp_dir, fastq paths, and the read-processing parameters — rt_primer GGGATGCAGCTCGCTCCTG with rt_mismatches 3, sss_mismatches 0, tn5_mismatches 1, ligation_mismatches 1, the barcode resource files (barcode_tn5.txt, barcode_ligation_104.txt, SSS barcode file), cutoff (reads per single cell, default 10000; example 2000), split_bam, hybrid_filter (e.g. NC_007605,hs37d5), additional_filter, process_only, and the aligner choice (bwa with a bowtie2_index for hg38/GRCh38). Launch with 'snakemake --configfile configs/config.yaml'; the container is pulled automatically from Dockerhub, or Apptainer can be used. On Hoffman2-like clusters install the cluster-generic executor plugin and the Hoffman2-specific plugin to submit Snakefile jobs. Rationale: mismatch tolerances control barcode recall during combinatorial barcode extraction, and the cutoff determines which single cells are retained downstream.

## Evaluation signals

- sample. parses as a dict of sample IDs, each with 'R1' and 'R2' lists of absolute FASTQ paths that exist on disk
- config.yaml contains all required keys: output_dir (with trailing /), temp_dir, fastqs, barcode files, rt/tn5/ligation/sss mismatch values (3/1/1/0), and cutoff
- Snakemake starts without error using 'snakemake --configfile configs/config.yaml' and pulls the Docker/Apptainer container successfully
- Downstream artifacts appear in output_dir: trimmed FASTQ files, trimmed. index, and (if split_bam: True) per-single-cell BAM files from bwa alignment
- The test configuration runs cleanly against the included tests/ fixtures, e.g. python fastq2.py --fastq_dir tests/fastqs/ and python trimmed2.py --fastq_dir tests/trimmed_fastq/

## Limitations

- No software version numbers are stated beyond the minimum snakemake 9.11.6; containers are pulled automatically from Dockerhub, so reproducibility depends on the unpinned remote image
- A changelog was not found for the repository, making version-to-version configuration differences hard to track
- Cutoff default is 10000 reads per single cell (example run uses 2000); misconfigured cutoffs directly change which single cells are retained
- When Apptainer is used instead of Docker, Apptainer must be installed separately by the user

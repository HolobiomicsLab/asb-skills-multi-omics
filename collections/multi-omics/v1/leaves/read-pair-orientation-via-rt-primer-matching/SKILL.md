# read-pair-orientation-via-rt-primer-matching

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Orients sci-L3 FASTQ read pairs by searching for the RT primer (GGGATGCAGCTCGCTCCTG, up to 3 mismatches) and third-round barcode, then appends the SSS barcode and IVT UMI to read names so downstream barcode extraction proceeds on a consistent orientation.

## When to use

Use when raw sci-L3 FASTQ read pairs arrive in unknown orientation and each read must be labeled with its SSS barcode and IVT UMI before first-round (Tn5) and second-round (ligation) barcode matching.

## When NOT to use

- Reads are already oriented and carry SSS barcode/IVT UMI in their names (i.e., downstream of this stage, e.g. input to sss_bam2.py on aligned BAMs)
- Library prep is not sci-L3 combinatorial indexing — the RT primer sequence, SSS barcode, and three-round barcode structure will not be present in the reads

## Inputs

- Raw paired-end FASTQ files (R1/R2) from a sci-L3 library, indexed via the sample.json produced by fastq2json.py
- config.yaml with rt_primer, rt_mismatches, sss_mismatches, tn5_mismatches, ligation_mismatches and barcode file paths
- Barcode resource files: barcode_tn5.txt, barcode_ligation_104.txt, and the SSS barcode file

## Outputs

- Annotated, adapter-trimmed FASTQ files with SSS barcode and IVT UMI appended to read names and an RNA-versus-DNA tag
- A trimmed. index file generated by trimmed2.py that indexes annotated trimmed FASTQs per sample for downstream stages

## How to apply

Parse config.yaml for the rt_primer sequence (GGGATGCAGCTCGCTCCTG), rt_mismatches (3), sss_mismatches (0), tn5_mismatches (1), and ligation_mismatches (1), plus the barcode resource files (barcode_tn5.txt, barcode_ligation_104.txt, SSS barcode file). For each read pair, search for the RT primer and third-round barcode allowing up to 3 Levenshtein-distance mismatches to determine orientation; on success, extract the SSS barcode and IVT UMI sequences and append them to the read names. Only then trim the Tn5 MEDS adapter with cutadapt and match the 8-nt Tn5 and 7-nt ligation barcodes against the provided lists (1 mismatch each). Emit the RNA-versus-DNA tag by detecting the rt_UMI versus GGGGGG signature and write annotated trimmed FASTQ files; then run trimmed2.py to build the trimmed. index per sample. Orientation must precede barcode matching because the SSS barcode and IVT UMI positions are only well-defined once the read pair is correctly oriented.


## Evaluation signals

- Every output read name carries an appended SSS barcode and IVT UMI, with sss_mismatches: 0 meaning SSS barcode calls must be exact matches
- The rt_UMI versus GGGGGG signature yields a consistent RNA-versus-DNA tag on each annotated read
- Downstream first/second-round barcode matching (8-nt Tn5, 7-nt ligation, 1 mismatch each) succeeds at the expected rate only for correctly oriented pairs
- trimmed2.py produces a trimmed. index whose per-sample entries cover all annotated trimmed FASTQ files

## Limitations

- Reads lacking the RT primer within rt_mismatches=3 cannot be oriented and are dropped from downstream barcode assignment
- SSS barcode extraction requires exact matching (sss_mismatches: 0), so sequencing errors in the SSS region cause read loss
- No software version numbers are stated for the pipeline's Docker/Apptainer containers, which may affect reproducibility of the orientation step
- Adding additional rounds of cell barcoding under the sci framework reduces the number of recovered single cells due to loss of per-cell coverage

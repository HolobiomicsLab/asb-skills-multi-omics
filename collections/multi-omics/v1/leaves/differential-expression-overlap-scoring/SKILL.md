# differential-expression-overlap-scoring

## Summary

Scores how faithfully simulated single-cell RNA-seq datasets reproduce differential expression (DEG) structure, using overlap-style metrics (ROUGE) alongside edgeRQLFDetRate-ratio, distribution-score, and SVM, then aggregates them into a per-method DEG-scenario functionality score.

## When to use

Use when benchmarking scRNA-seq simulation methods on their ability to regenerate ground-truth differential expression between cell groups, or when reproducing the paper's DEG functionality scores (e.g., Lun = 0.90) from simmethods/simpipe outputs.

## When NOT to use

- When the goal is accuracy benchmarking (fitting real-data distributions) rather than functionality with ground truth — use the paper's accuracy evaluation with SRTsim, scDesign3, ZINB-WaVE, and scDesign2 instead
- When simulating cell batches or differentiation trajectories — those scenarios require CMS/LISI/MM/entropy/kBET/PCR or Slingshot-based HIM/F1branches/F1milestones/Cordist metrics, not DEG overlap scoring
- When the method cannot simulate DEGs between groups at all — such methods fail parameter estimation or produce missing/infinite values and should be recorded as execution errors rather than scored

## Inputs

- Real scRNA-seq reference datasets (from the 152 reference datasets across 24 platforms) with ground-truth cell-group and DEG annotations
- Simulated count matrices generated by simmethods/simpipe for each evaluated method (e.g., Lun, SPARSim, scMultiSim, Lun2)
- Ground-truth DEG labels for simulated data (specified cell groups / differential expression parameters)

## Outputs

- Per-method DEG-scenario functionality scores (aggregated from edgeRQLFDetRate-ratio, distribution-score, SVM, and ROUGE)
- functionality_scores.csv containing scores for all methods and scenarios
- Ranked comparison of methods (e.g., Lun = 0.90 on DEGs; Lun = 0.71 on cell groups)

## How to apply

Install the simulation stack with devtools::install_github("duohongrui/simmethods") and devtools::install_github("duohongrui/simpipe"). For each candidate simulator (e.g., Lun, SPARSim, scMultiSim, Lun2), simulate datasets from 152 real reference datasets with ground-truth group/DEG annotations using the simpipe pipeline, optionally via the simpipe Docker image through simpipe2docker. On each simulated dataset, compute the DEG-scenario metrics — edgeRQLFDetRate-ratio, distribution-score, SVM, and the overlap-based ROUGE score comparing simulated vs. real DEG sets — since the cell-groups and DEG scenarios share ASW, Dunn, Connectivity, DB, CDI, and ROUGE. Aggregate the per-dataset metric results into a single DEG-scenario functionality score per method and write results to functionality_scores.csv. Validate by checking that the reproduced scores match reported values (Lun: 0.90 for DEGs, 0.71 for cell-groups) and that Lun, SPARSim, and scDesign3-tree rank highest in their respective scenarios.

## Evaluation signals

- Reproduced DEG functionality scores match reported values: Lun = 0.90 (DEGs) and 0.71 (cell-groups)
- Lun, SPARSim, and scDesign3-tree outperform other methods in their corresponding simulation scenarios
- Per-method scores are written to functionality_scores.csv covering all four scenarios (cell-groups, DEGs, cell-batches, trajectory)
- SPARSim reaches 0.77 on cell-batches and scMultiSim 0.56 / Lun2 0.53 as reported, confirming pipeline consistency
- Methods that fail produce execution errors traceable to failed parameter estimations or missing/infinite values rather than spuriously low overlap scores

## Limitations

- Methods relying solely on customized parameters (Splat, SCRIP, Lun, scMultiSim) may cause data distortion and over-simulation when generating ground-truth datasets
- Lun does not account for the sparsity and biological variability of scRNA-seq data
- Excessively flexible parameter settings can distort simulated data so it no longer reflects real biological changes
- No method performs best on all criteria; trade-offs between accuracy, functionality, and scalability must be considered

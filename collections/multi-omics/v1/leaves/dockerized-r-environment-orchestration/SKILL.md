# Dockerized R environment orchestration

## Summary

Run the simpipe single-cell/spatial transcriptomics simulation pipeline inside the duohongrui/simpipe Docker image, using the simpipe2docker R package to link the local R environment to the container so 49 simulators run in a reproducible, pre-configured environment.

## When to use

Use when local installation of simmethods/simpipe (and tislingshot) is impractical due to dependency conflicts, and a reproducible containerized R setup is needed to execute scRNA-seq/SRT simulations.

## When NOT to use

- When the analysis does not involve single-cell/spatial transcriptomics simulation — the simpipe image is purpose-built for simmethods/simpipe workflows
- When Docker cannot be installed or the daemon cannot run (e.g., restricted HPC environments without container support); use direct GitHub installation of simmethods/simpipe instead
- When simulating datasets with trajectory information, remember the container must include tislingshot; otherwise install it per the standard (non-Docker) route

## Inputs

- Reference scRNA-seq or SRT datasets (e.g., from the 152 reference datasets / Additional file 2, Tables S1–S3 of DOI 10.1186/s13059-024-03290-y)
- Running Docker daemon (Docker Desktop) with the duohongrui/simpipe:latest image pulled
- R session with devtools and simpipe2docker installed

## Outputs

- Simulated single-cell or spatial transcriptomics datasets generated by simpipe-wrapped simulators inside the container
- Parameter estimates from real data computed within the containerized pipeline
- Evaluation results of simulated data from general and functional perspectives

## How to apply

Install Docker Desktop, then install the simpipe2docker package with devtools::install_github('duohongrui/simpipe2docker'). Verify the daemon with simpipe2docker::test_docker_installation(detailed = TRUE), which checks installation, daemon status, version >1.0, linux mode, image pulling/running, and volume mounting. Pull the image via 'docker pull duohongrui/simpipe:latest' or babelwhale::pull_container(container_id = 'duohongrui/simpipe:latest'). Then use simpipe2docker to link the R environment and the Docker container and execute the parameter-estimation/simulation/evaluation pipeline; documentation lives at Simsite. The rationale is that the container ships simmethods, simpipe, and dependencies pre-installed, avoiding fragile GitHub installs while preserving reproducibility.

## Related tools

- **simpipe2docker** (R package that links the local R environment to the simpipe Docker container and dispatches simulations to it) — https://github.com/duohongrui/simpipe2docker
- **simpipe** (The containerized pipeline (also published as a Docker image) for estimating parameters from real data, simulating, and evaluating simulated single-cell data) — https://github.com/duohongrui/simpipe
- **simmethods** (Collection of the 49 simulation methods bundled inside the container that simpipe executes) — https://github.com/duohongrui/simmethods
- **babelwhale** (Used to pull the duohongrui/simpipe:latest container image from within R)

## Examples

```
simpipe2docker::test_docker_installation(detailed = TRUE); babelwhale::pull_container(container_id = "duohongrui/simpipe:latest")
```

## Evaluation signals

- simpipe2docker::test_docker_installation(detailed = TRUE) returns TRUE with all checks passed (daemon running, version >1.0, linux mode, can pull/run images, can mount temporary volumes)
- 'docker pull duohongrui/simpipe:latest' completes and the image is present locally (babelwhale::pull_container succeeds)
- Simulations launched through simpipe2docker produce simulated datasets whose evaluation metrics match those from a native (non-Docker) simpipe run on the same reference dataset
- Container runs complete without the execution errors the paper attributes to failed parameter estimations or missing/infinite values in calculations

## Limitations

- The Docker route mirrors the local install: trajectory-information simulation still requires tislingshot, so trajectory scenarios may need the standard GitHub install (dynverse/ti_slingshot) if not bundled
- Execution errors in the underlying simulations are mainly caused by failed parameter estimations and appearance of missing or infinite values in calculations — containerization does not remove method-level failures
- Docker Desktop must be installed and the daemon running with correct version (>1.0), linux mode, and volume-mount capability before the workflow can start

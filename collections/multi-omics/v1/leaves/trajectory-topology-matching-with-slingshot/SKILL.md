# Trajectory topology matching with Slingshot

## Summary

Evaluates the functionality of single-cell RNA-seq simulation methods under the trajectory scenario by using Slingshot-based metrics (HIM, F1branches, F1milestones, Cordist) to compare simulated differentiation trajectories against the simulated ground truth.

## When to use

Use when benchmarking or validating scRNA-seq simulators that generate datasets with differentiation trajectory information, and you need to quantify whether simulated trajectories preserve the ground-truth topology.

## When NOT to use

- The evaluation target is a different simulation scenario (cell groups, DEGs, or cell batches) — those use ASW/Dunn/Connectivity/DB/CDI/ROUGE or CMS/LISI/MM/entropy/kBET/ASW-batch/PCR metrics instead
- The simulated data has no ground-truth trajectory information, since Slingshot-based topology metrics require milestone/branch ground truth to compare against

## Inputs

- Simulated scRNA-seq datasets with ground-truth trajectory annotations generated by simmethods/simpipe
- Reference trajectory topology (milestones and branch structure) from the simulated ground truth
- Trajectory functionality scores CSV (functionality_scores.csv) for aggregation

## Outputs

- Per-method trajectory metric values (HIM, F1branches, F1milestones, Cordist)
- Aggregated per-scenario trajectory functionality score written to functionality_scores.csv
- Identification of best trajectory-scenario method (scMultiSim, score = 0.56)

## How to apply

Simulate datasets containing trajectory ground truth using the simmethods/simpipe pipeline; trajectory simulation requires the tislingshot package, installed via devtools::install_github("dynverse/ti_slingshot/package/"). Infer trajectories from the simulated expression data and compare them to the ground truth using Slingshot-based metrics: HIM (topology distance), F1branches, F1milestones, and Cordist (correlation of distance matrices). Aggregate the metric results into a per-method trajectory functionality score and write it to functionality_scores.csv. Judge correctness by checking reproduced scores against reported values (scMultiSim = 0.56, Lun2 = 0.53) and verifying that Class1 methods show poor performance on F1milestones and Cordist.

## Evaluation signals

- Reproduced trajectory-scenario functionality scores match reported values: scMultiSim = 0.56 and Lun2 = 0.53
- Class1 methods show poor performance specifically on F1milestones and Cordist metrics
- All four trajectory metrics (HIM, F1branches, F1milestones, Cordist) are computed for each evaluated method
- Scores are aggregated per method and written to functionality_scores.csv
- Trajectory simulation runs successfully only when tislingshot is installed beforehand

## Limitations

- Class1 (kinetic-model-based) methods neglect characterization of gene expression and variability from real data, yielding poor F1milestones and Cordist performance
- Methods relying solely on customized parameters (Splat, SCRIP, Lun, scMultiSim) may cause data distortion and over-simulation when generating ground-truth datasets
- No method performs best on all criteria, so trajectory scores should be weighed against accuracy and scalability trade-offs
